# TOEIC Studio · Database, Node.js API & React Admin

Ứng dụng học **Từ vựng + TOEIC Reading** (Part 5, 6, 7): Express 5 + Node.js 24, PostgreSQL 16, React 19 và Vite 7. Backend phục vụ cả REST API và bản build React trên cùng domain. Không có phần Listening.

## Hiện trạng

- Database đã chuyển từ MySQL sang **PostgreSQL** (driver `pg`). Schema, migration, seed và test API chạy trên PostgreSQL 16.
- Phạm vi nội dung chỉ còn TOEIC Reading: Part 5 (30 câu), Part 6 (16 câu), Part 7 (54 câu); đề Reading chuẩn 100 câu / 75 phút.
- Bản deploy Railway cũ (https://toeic-api-production-8b44.up.railway.app) vẫn dùng MySQL cho tới khi deploy lại với dịch vụ PostgreSQL (xem phần Triển khai Railway).
- Seed demo có 8 từ, 1 bài ngữ pháp, 5 câu Reading tự biên soạn (1 email Part 7 kèm bản dịch), 1 bộ Part 5 và 1 mini test.

## Database (PostgreSQL)

File: `backend/schema.sql`. Kiểu enum dùng `VARCHAR + CHECK`, khóa chính `INTEGER GENERATED BY DEFAULT AS IDENTITY`, thời gian `TIMESTAMPTZ` (UTC), snapshot bài làm `JSONB`, `updated_at` cập nhật bằng trigger.

| Nhóm | Bảng |
|---|---|
| Người dùng | `users` (`password_hash` có thể NULL với tài khoản Google, `firebase_uid` duy nhất, `last_login_at`, `avatar_url`, `target_score` theo thang Reading 5–495; CHECK bắt buộc có mật khẩu hoặc Firebase UID) |
| Từ vựng hệ thống | `vocabulary_topics`, `vocabularies` (IPA, nghĩa, ví dụ + dịch, đồng/trái nghĩa, ảnh, audio phát âm tùy chọn) |
| Ngữ pháp | `grammar_topics`, `grammar_lessons` |
| TOEIC Reading | `toeic_parts` (chỉ 5–7), `question_groups` (Part 6/7), `reading_passages` (1–3 đoạn/nhóm, loại văn bản, bản dịch, ảnh), `questions` (có `question_type` để thống kê lỗi), `question_options` (luôn 4 đáp án A–D) |
| Luyện tập / thi thử | `practice_sets`, `practice_set_questions`, `mock_tests`, `mock_test_questions` |
| Bài làm | `practice_attempts`, `practice_answers`, `mock_test_attempts` (`part5/6/7_correct`), `mock_test_answers` |
| Tiến độ | `user_vocabulary_progress`, `user_grammar_progress` |
| **Bộ thẻ flashcard** | `flashcard_decks` (ảnh bìa tùy chọn), `flashcards` (**ảnh tùy chọn**, ghim, liên kết từ điển, lịch ôn SM-2) |
| **Lịch sử tra từ** | `lookup_history` (mỗi từ một dòng/người dùng, đếm số lần tra, nguồn tra: từ điển / bài đọc / flashcard) |
| **Thông báo** | `notifications` (loại, nội dung, `data` JSONB để điều hướng trong app, trạng thái đã đọc) |
| Quản trị | `audit_logs`, `schema_migrations` |

Ảnh được lưu dưới dạng URL HTTP(S) (database có CHECK). Android upload ảnh lên object storage rồi gửi URL; có endpoint upload avatar đã kiểm tra nội dung ảnh.

## Chức năng

- JWT 15 phút và refresh token 30 ngày; admin web sử dụng HttpOnly cookie; Android sử dụng Bearer token.
- Đăng ký/đăng nhập Google qua **Firebase Authentication**: Android gửi Firebase ID token tới `POST /api/auth/firebase`, server kiểm tra token rồi cấp JWT của hệ thống. Tài khoản Google không cần mật khẩu; email đã đăng ký bằng mật khẩu được liên kết tự động.
- Đăng ký học viên, đăng nhập, khóa/vô hiệu hóa người dùng, mục tiêu điểm Reading.
- CRUD chủ đề/từ vựng, chủ đề/bài ngữ pháp, nhóm câu hỏi, đoạn văn Reading, câu hỏi và đáp án, bộ luyện, đề thi, danh sách câu theo thứ tự.
- Part 5 là câu đơn (không gắn nhóm). Part 6–7 chỉ xuất bản khi nhóm có ít nhất một đoạn văn; Part 6 tối đa 1 đoạn, Part 7 tối đa 3 đoạn. Không sửa đoạn văn khi nhóm còn câu đã xuất bản.
- Bắt đầu/nộp/xem lại luyện tập và thi thử; snapshot câu hỏi, đoạn văn và đáp án lúc bắt đầu; chấm trên server trong transaction, khóa hàng chống nộp trùng. Trước khi nộp không trả đáp án, giải thích hoặc bản dịch đoạn văn.
- Kết quả thi thử có số câu đúng theo Part 5/6/7 và tự tạo thông báo loại `RESULT`.
- Học viên: bộ thẻ flashcard có ảnh, thêm thẻ từ từ điển, ghim thẻ, ôn tập SM-2; tra từ điển và lịch sử tra từ; danh sách thông báo, đánh dấu đã đọc, ẩn thông báo.
- Admin: gửi thông báo cho tất cả học viên hoặc danh sách người dùng (`POST /api/admin/notifications/broadcast`); xem bộ thẻ, lịch sử tra từ, thông báo ở chế độ chỉ đọc.
- Dashboard: số người dùng/nội dung/bài làm, độ chính xác trung bình, nhịp học 14 ngày UTC, độ phủ Part 5–7 so với số câu đề chuẩn và nhật ký admin.
- Validation, parameterized SQL, foreign keys, CHECK constraints, Helmet, rate limits, kiểm tra origin/CSRF, bảo vệ quản trị viên cuối cùng.

## Chạy trên máy khác

1. Cài Node.js 24, pnpm 12.14.0 và PostgreSQL 16 (bộ cài Windows hoặc `docker compose up -d postgres`). Tạo user và database:

```sql
CREATE USER toeic PASSWORD 'mat-khau-manh';
CREATE DATABASE toeic OWNER toeic ENCODING 'UTF8';
```

2. Copy `.env.example` thành `.env`, đặt `DATABASE_URL=postgresql://toeic:<mật khẩu URL-encoded>@127.0.0.1:5432/toeic`, JWT secret ngẫu nhiên tối thiểu 32 ký tự, email và mật khẩu admin tối thiểu 12 ký tự. Database có SSL bắt buộc (cloud) thì thêm `DB_SSL=true`.
3. Chạy:

```sh
pnpm install --frozen-lockfile
pnpm migrate
pnpm seed
pnpm build
pnpm dev
```

Đăng nhập Google (Firebase):

1. Firebase Console: tạo project, thêm app Android (package name + SHA-1 của keystore), bật **Authentication > Sign-in method > Google**, tải `google-services.json` vào app Android.
2. Đặt `FIREBASE_PROJECT_ID=<project-id>` trong `.env` (Railway/compose: biến môi trường). Server chỉ cần Project ID và truy cập được `www.googleapis.com` để lấy khóa công khai; không cần service account.
3. Android: Google Sign-In → `signInWithCredential(GoogleAuthProvider.getCredential(idToken, null))` → `getIdToken(true)` → gửi `POST /api/auth/firebase`.

Muốn nội dung mẫu: thêm `SEED_DEMO=true` vào `.env` trước khi seed. Seed mặc định chỉ tạo admin và 3 Part Reading. Seed không đổi mật khẩu admin đã tồn tại.

Dữ liệu MySQL cũ không tự chuyển sang; schema mới khác cấu trúc (bỏ Listening, đoạn văn tách bảng). Với database demo, chạy migrate + seed lại trên PostgreSQL là đủ.

React phát triển riêng: `pnpm exec vite --host 127.0.0.1`; backend vẫn chạy port 3000. Khi chạy React dev server riêng, đổi `APP_ORIGIN` sang origin của Vite.

Kiểm tra: `pnpm test`. Test ưu tiên `.env.test` nếu có; cấu hình database test riêng trước khi chạy. CI dùng database PostgreSQL riêng từ biến môi trường. Không chạy test với database production.

`start-local.ps1` kiểm tra PostgreSQL đang chạy theo `DATABASE_URL` rồi mở app; `stop-local.ps1` chỉ dừng app.

## Triển khai Railway

Bản deploy hiện tại dùng MySQL. Để chuyển sang PostgreSQL:

1. Trong project Railway, thêm dịch vụ **PostgreSQL**. App service đặt root directory là `/server`.
2. App service đặt `DATABASE_URL` bằng reference `${{Postgres.DATABASE_URL}}` (private network); không dùng public URL cho app.
3. Giữ `JWT_SECRET`, `FIREBASE_PROJECT_ID`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `ADMIN_NAME`, `NODE_ENV=production`, `TRUST_PROXY=true`, `SEED_DEMO=false`, `APP_ORIGIN=https://<domain>`.
4. Deploy. Container áp dụng schema, tạo admin nếu chưa có, rồi mở server. `/api/health` trả `database: "postgresql"` khi kết nối thành công.
5. Kiểm tra HTTPS, đăng nhập, CRUD và luồng học viên trên URL public, rồi xóa dịch vụ MySQL cũ khi không còn cần dữ liệu.

Tài liệu chính thức: [PostgreSQL trên Railway](https://docs.railway.com/databases/postgresql), [biến tham chiếu](https://docs.railway.com/variables).

## Triển khai VPS / EC2

Trên Ubuntu có Docker Compose và domain trỏ về máy:

1. Copy source và tạo `.env` trên server với `POSTGRES_PASSWORD`, `DEPLOY_DATABASE_URL=postgresql://toeic:<URL-encoded-password>@postgres:5432/toeic`, `JWT_SECRET`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `APP_ORIGIN=https://admin.example.com`.
2. Chạy `docker compose up -d --build`. PostgreSQL chỉ ở mạng nội bộ Compose; app chỉ bind cổng máy chủ `127.0.0.1:3000`.
3. Cài Caddy, thay domain trong `deploy/Caddyfile`, reverse proxy đến `127.0.0.1:3000`; mở 80/443. Không mở port 5432.
4. Kiểm tra HTTPS và `/api/health`, rồi kiểm tra đăng nhập public.

Volume `postgres-data` chứa dữ liệu. `docker compose down` giữ volume; không dùng `down -v` nếu cần giữ dữ liệu. Backup bằng `pg_dump` trước khi cập nhật schema. Runner áp dụng schema v1 và các migration có version trong backend/migrations; version 2 bổ sung phiên Auth. Không chỉ sửa schema.sql để nâng cấp database đã tồn tại.

## Giới hạn có chủ ý

- Kết quả là số câu đúng và phần trăm, không gán điểm TOEIC chuẩn ETS hoặc quy đổi giả.
- Đề thi có thể là mini test; hiện không ép đủ 100 câu Reading (30/16/54) khi xuất bản.
- Ảnh nội dung nhập qua HTTP(S) URL; avatar upload qua /api/auth/me/avatar, lưu local volume hoặc S3 tùy cấu hình.
- Đã có reset password bằng OTP email; SMTP cần được cấu hình thật. Chưa có autosave từng câu hoặc kiểm tra bản quyền kho đề.
- App Android nằm ở thư mục `../android`; tích hợp qua API, xem [`docs/API.md`](../docs/API.md) và [`docs/openapi.yaml`](../docs/openapi.yaml).
- CI/CD thực tế cần repository/tài khoản của bạn; source có workflow GitHub Actions để build và test với PostgreSQL khi push.

## Kiểm thử kết nối và transaction

Kết nối PostgreSQL chờ tối đa 5 giây để báo lỗi sớm khi database không truy cập được. Nếu rollback cũng lỗi, backend giữ nguyên lỗi gốc và loại kết nối lỗi khỏi pool; client luôn được giải phóng.

Chạy kiểm thử helper database không cần PostgreSQL hoặc file .env: `node --test tests/db.test.js`. CI chạy build và toàn bộ test API trên PostgreSQL 16 riêng, từ thư mục server/.

Chi tiết B1.1 và B1.2: ../docs/B1_AUTH.txt. Kết quả kiểm thử: ../docs/B1_TEST_RESULTS.txt. Trên máy đã cài PostgreSQL local, chạy ./start-database.ps1 trước ./start-local.ps1.

B1.3, bảo mật, cleanup và admin: ../docs/B1_3_OPERATIONS.txt. Triển khai VPS: deploy/VPS_DEPLOYMENT.txt. Chưa triển khai cloud; cần SMTP thật để gửi OTP ra Internet.


B2.1 Course / Practical Reading

Sau pnpm migrate và pnpm seed, chạy pnpm content:import để nhập bộ nội dung TV3 đã kiểm tra, rồi pnpm course:seed để tạo lộ trình. Seed chạy lại không ghi đè chỉnh sửa của người quản trị hoặc nhân bản bài. Chạy lại course:seed sau khi thêm nội dung. Server yêu cầu migration tối thiểu phiên bản 5.

GET /api/learn/path và /api/learn/readings dùng dữ liệu thật và tiến độ của người đăng nhập. Hướng dẫn tích hợp: ../docs/B2_1_COURSE_READING.txt. Phần Android vẫn cần nối repository và màn Reading với API này.


B2.2 Quiz / Thi thử

Chạy pnpm migrate rồi pnpm quiz:import để thêm ba bộ quiz đã kiểm tra (9 câu). Server cần schema phiên bản 6. pnpm attempts:expire chốt bài quá hạn theo lô; server tự chạy maintenance lúc mở và mỗi 15 phút.

Thi thử hỗ trợ lưu nháp có answer_version, cờ xem lại, snapshot và nộp lặp an toàn. Đề TV3 đủ 100 câu trong 75 phút. Quiz có feedback lần đầu cho FILL_BLANK/MATCH/ORDER. Xem ../docs/B2_2_QUIZ_EXAMS.txt để nối Android.

Container có cả thư mục content. Khi dùng env từ nền tảng thay vì file .env, có thể nhập nội dung bằng node scripts/import-content.js, node scripts/seed-course.js và node scripts/import-quizzes.js bên trong container sau migrate/seed. Docker CMD chưa tự nhập nội dung; chỉ nhập khi đã rà soát bộ nội dung muốn xuất bản.
